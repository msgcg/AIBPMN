## 1. Системные требования

- **Python**: версия `3.10`, `3.11`, `3.12` или более новая (поддерживается и протестировано вплоть до `3.14`).
- **Операционная система**:
  - Windows 10 / 11 (рекомендуется PowerShell 7+ и Windows Terminal).
  - Linux (Ubuntu 22.04+, Debian 12+, Rocky Linux 9+).
  - macOS 12+ (Monterey, Ventura, Sonoma).
- **Сетевой доступ**: исходящее HTTPS-подключение к API Сбера (`https://ngw.devices.sberbank.ru:9443` и `https://gigachat.devices.sberbank.ru`).
- **Браузер**: современный веб-браузер с поддержкой ES6+ и SVG (Yandex Browser, Chrome, Edge, Firefox, Safari).

## 2. Подготовка окружения и установка зависимостей

### Windows 11 / 10 (PowerShell)

1. Откройте **Windows Terminal** или **PowerShell**.
2. Перейдите в корневую директорию проекта:

   ```powershell
   cd "C:\path\to\AIBPMN"
   ```
3. Создайте виртуальное окружение Python:

   ```powershell
   python -m venv .venv
   ```
4. Если при активации возникает ошибка выполнения скриптов (`execution of scripts is disabled on this system`), разрешите запуск локальных скриптов для текущего пользователя:

   ```powershell
   Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
   ```
5. Активируйте виртуальное окружение:

   ```powershell
   .\.venv\Scripts\Activate.ps1
   ```
6. Обновите `pip` и установите зависимости проекта:

   ```powershell
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

### Linux / macOS (Bash / Zsh)

1. Откройте терминал и перейдите в папку проекта:

   ```bash
   cd /path/to/AIBPMN
   ```
2. Создайте и активируйте виртуальное окружение:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```
3. Обновите `pip` и установите зависимости:

   ```bash
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

## 3. Получение и настройка API-ключа Сбер GigaChat

Для работы генеративного ИИ-архитектора требуется доступ к **GigaChat API**:

1. Перейдите на портал разработчиков Сбера: [developers.sber.ru](https://developers.sber.ru/).
2. Войдите с помощью **Сбер ID**.
3. Перейдите в раздел **«Кабинет»** -> **«GigaChat API»**.
4. Создайте новый проект (для физических лиц предоставляется бесплатный ежемесячный пакет токенов).
5. В созданном проекте скопируйте **«Авторизационные данные»** (строка в формате Base64 либо пара `Client ID` и `Client Secret`).
6. Укажите скопированное значение в параметре `GIGACHAT_AUTH_KEY` в файле `.env`.

> [!NOTE]
> В AIBPMN встроен автоматический менеджер OAuth-токенов: система самостоятельно запрашивает временный токен доступа у шлюза Сбера и обновляет его каждые 30 минут без необходимости перезапуска сервера.

## 4. Конфигурация переменных окружения (.env)

### Режим разработки (Development)

1. Скопируйте шаблон `.env.example` в файл `.env`:

   - **PowerShell**:
     ```powershell
     Copy-Item .env.example .env
     ```
   - **Bash**:
     ```bash
     cp .env.example .env
     ```
2. Откройте файл `.env` в текстовом редакторе и настройте параметры:

   ```dotenv
   # Режим окружения: dev
   DJANGO_ENV=dev
   DJANGO_DEBUG=True
   DJANGO_SECRET_KEY=django-insecure-aibpmn-architecture-suite-2026-key

   # Разрешенные хосты (через запятую)
   DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1

   # Авторизация GigaChat (API Сбера)
   GIGACHAT_AUTH_KEY=ВАШ_КЛЮЧ_АВТОРИЗАЦИИ_GIGACHAT
   GIGACHAT_SCOPE=GIGACHAT_API_PERS
   GIGACHAT_MODEL=GigaChat-3-Ultra
   ```

   **Параметры Scope:**
   - `GIGACHAT_API_PERS` — для физических лиц (по умолчанию).
   - `GIGACHAT_API_CORP` — для юридических лиц и корпоративных контрактов.

   **Параметры моделей:**
   - `GigaChat-3-Ultra` — флагманская модель с максимальным качеством проектирования архитектуры процессов.
   - `GigaChat-Pro` — быстрая продвинутая модель.
   - `GigaChat` — базовая облегченная модель.

### Режим промышленной эксплуатации (Production)

Для развертывания на боевом сервере используйте шаблон `.env.production.example`:

```dotenv
DJANGO_ENV=production
DJANGO_DEBUG=False

# Сгенерируйте уникальный секретный ключ (не менее 50 символов)
DJANGO_SECRET_KEY=generate-a-strong-random-secret-key-here-minimum-50-characters

# Доменные имена вашего сервера
DJANGO_ALLOWED_HOSTS=aibpmn.yourdomain.com,127.0.0.1,localhost

# Доверенные источники для защиты от CSRF (с протоколом https://)
DJANGO_CSRF_TRUSTED_ORIGINS=https://aibpmn.yourdomain.com

# Настройки безопасности SSL и cookie (включайте True при работе за HTTPS/Nginx)
DJANGO_COOKIE_SECURE=True
DJANGO_SECURE_SSL_REDIRECT=True
DJANGO_HSTS_SECONDS=31536000

# Авторизация GigaChat
GIGACHAT_AUTH_KEY=ВАШ_БОЕВОЙ_КЛЮЧ_GIGACHAT
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-3-Ultra
```

## 5. База данных, миграции и автосоздание администратора

Проект использует реляционную базу данных SQLite (`db.sqlite3` в корне проекта). Файл базы данных исключен из Git-репозитория (`.gitignore`), чтобы отладочные изменения никогда не попадали в коммиты.

1. Примените миграции схемы данных:

   ```powershell
   python manage.py migrate
   ```

2. **Учетная запись администратора и пользователя по умолчанию**:
   В системе реализовано автоматическое создание и самовосстановление стандартной учетной записи (срабатывает при `migrate`, при первом HTTP-запросе к серверу через `AutoBootstrapAdminMiddleware`, а также непосредственно при входе через `AdminAutoCreateBackend`):
   - **Логин**: `max`
   - **Пароль**: `Admin2026!Bpmn`
   - **Панель администратора Django**: [http://127.0.0.1:8000/admin/](http://127.0.0.1:8000/admin/)
   - **Основной интерфейс приложения**: [http://127.0.0.1:8000/](http://127.0.0.1:8000/) (можно войти через кнопку «Войти» под теми же данными `max` / `Admin2026!Bpmn`).

3. **Очистка базы данных после отладки (`reset_db`)**:
   Если в ходе отладки были созданы тестовые пользователи, проекты и история сообщений, вернуть базу данных в эталонное чистое состояние (оставив только пустого пользователя/администратора `max`) можно одной командой:

   ```powershell
   python manage.py reset_db
   ```

## 6. Способы запуска приложения

### Способ 1: Режим разработки через терминал

```powershell
python manage.py runserver
```

Сервер запустится по адресу: `http://127.0.0.1:8000/`.

Для прослушивания всех сетевых интерфейсов (например, для тестирования с мобильного устройства в локальной сети):

```powershell
python manage.py runserver 0.0.0.0:8000
```

---

### Способ 2: Запуск и отладка в Visual Studio Code (F5)

В директории `.vscode/launch.json` настроены готовые профили запуска:

1. Откройте папку проекта `AIBPMN` в **VS Code**.
2. Убедитесь, что выбран интерпретатор из `.venv`.
3. Откройте вкладку **Run and Debug** (`Ctrl+Shift+D`).
4. Выберите профиль:
   - **`Django: Отладка (Development / Dev)`** — запуск сервера разработки на `0.0.0.0:8000` с дебаггером и автоперезагрузкой.
   - **`Django: Продакшн (Production / Prod)`** — запуск с настройками `prod.py` и флагом `--insecure` для раздачи статики.
   - **`Django: Тесты (Run Tests)`** — запуск полного набора автотестов.
5. Нажмите клавишу **F5**.


### Способ 4: Промышленное развертывание на Linux-сервере (Gunicorn + Nginx)

1. Соберите статические файлы:
   ```bash
   python manage.py collectstatic --noinput
   ```
2. Установите WSGI-сервер `gunicorn`:
   ```bash
   pip install gunicorn
   ```
3. Пример юнита **systemd** (`/etc/systemd/system/aibpmn.service`):
   ```ini
   [Unit]
   Description=AIBPMN Architect Django Application
   After=network.target

   [Service]
   User=www-data
   Group=www-data
   WorkingDirectory=/var/www/AIBPMN
   ExecStart=/var/www/AIBPMN/.venv/bin/gunicorn \
       --workers 3 \
       --bind 127.0.0.1:8000 \
       aibpmn_project.wsgi:application
   Restart=always

   [Install]
   WantedBy=multi-user.target
   ```
4. Пример конфигурации **Nginx** (`/etc/nginx/sites-available/aibpmn`):
   ```nginx
   server {
       listen 80;
       server_name aibpmn.yourdomain.com;
       return 301 https://$host$request_uri;
   }

   server {
       listen 443 ssl http2;
       server_name aibpmn.yourdomain.com;

       ssl_certificate /etc/letsencrypt/live/aibpmn.yourdomain.com/fullchain.pem;
       ssl_certificate_key /etc/letsencrypt/live/aibpmn.yourdomain.com/privkey.pem;

       client_max_body_size 25M;

       location /static/ {
           alias /var/www/AIBPMN/staticfiles/;
           expires 30d;
           access_log off;
       }

       location / {
           proxy_pass http://127.0.0.1:8000;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }
   }
   ```

## 7. Работа с ИИ-архитектором, валидацией, прикрепленными документами и трейсингом

### Прикрепление регламентов к сообщению чата
- Нажмите на кнопку со скрепкой рядом с полем ввода чата и выберите файл регламента (`.pdf`, `.docx`, `.md`, `.txt`, `.json`, `.csv`, `.xml`).
- Текст документа автоматически извлекается и передается ИИ-архитектору вместе с вашим запросом.
- В отправленном сообщении пользователя отображается компактная карточка документа с бейджем формата и подсказкой «Откройте для просмотра».

### Интерактивный трейсинг (Фраза <-> Код DSL <-> Элемент BPMN)
- **Клик по элементу на диаграмме BPMN**:
  - В редакторе кода BPMN-as-Code подсвечиваются и прокручиваются в видимую область строки объявления этого элемента и всех его связей.
  - В сообщении пользователя в чате подсвечивается исходное предложение, из которого был построен данный шаг.
  - Если процесс построен по прикрепленному файлу, под карточкой файла в чате появляется плашка с цитатой из документа, а в открытом окне документа автоматически выделяется и прокручивается соответствующий фрагмент текста.
- **Перетаскиваемое окно просмотра документа**:
  - Нажмите на карточку прикрепленного файла в чате, чтобы открыть компактное модальное окно с текстом документа.
  - Потяните окно за верхний заголовок мышью или пальцем, чтобы расположить его в любой удобной части экрана параллельно со схемой.
  - Кликните по любому подсвеченному предложению внутри окна документа — соответствующий блок сразу выделится на BPMN-схеме и в редакторе кода.

### Контроль логических разрывов и раскрываемые карточки анализа
- **Детекция логических разрывов**: если в исходном описании отсутствует логическая связь между шагами, система не соединяет их вымышленной стрелкой, оставляя разрыв потока управления на схеме для наглядной визуализации проблемы в бизнес-требованиях.
- **Раскрываемый блок «Отчет валидации процесса»**: содержит сводку по стартовым и конечным событиям, задачам, шлюзам, циклам возврата и найденным логическим разрывам. Нажмите на заголовок блока, чтобы развернуть или свернуть подробности.
- **Раскрываемый блок «Уточняющие вопросы по регламенту»**: содержит вопросы по недостающим веткам, ролям или разрывам, а также кнопки быстрых ответов (чипы), подставляющие ответ в чат в один клик.

## 8. Запуск автоматических тестов

В проекте реализован набор из **86 автоматических тестов**, проверяющий все подсистемы:

- Регистрацию, валидацию паролей, вход, автосоздание и самовосстановление администратора `max`, смену пароля и удаление аккаунтов.
- Изоляцию проектов пользователей и работу гостевого режима.
- Парсинг, компиляцию BPMN-as-Code в BPMN 2.0 XML и обратную декомпиляцию XML в DSL.
- Автоповторы генерации при синтаксических ошибках (до 5 попыток), формирование отчета валидации, проактивных вопросов и извлечение трейсинга (включая морфологическое сопоставление для русских текстов и прикрепленных документов `.md`, `.docx`, `.pdf`).
- Загрузку, Base64-кодирование, фильтрацию и скачивание файлов базы знаний.
- Работу PWA, манифеста, безопасного Service Worker, `robots.txt` и `sitemap.xml`.

Для запуска тестов выполните:

```powershell
python manage.py test architect
```

Ожидаемый результат:

```text
Ran 86 tests in ...s
OK
```

## 9. Progressive Web App (PWA) и кроссплатформенная установка

Приложение поддерживает установку как PWA на всех платформах:
- **Android**: через пункт меню браузера «Установить приложение».
- **iOS / iPadOS (Safari)**: кнопка «Поделиться» -> «На экран Домой».
- **Windows / macOS / Linux**: иконка установки в адресной строке браузера («Установить AIBPMN Architect»).

### Особенности Service Worker (`sw.js`) и безопасность Django
- Навигационные переходы (`mode: 'navigate'`), не-GET запросы (`POST`, `PUT`, `DELETE`) и любые обращения к `/api/` и `/admin/` не перехватываются воркером и всегда идут напрямую к серверу Django, что исключает конфликты с CSRF-токенами и сессиями.
- Service Worker кеширует только статические файлы (CSS, JS, шрифты, иконки).


## 11. Работа с базой знаний и RAG

Персональная база знаний позволяет ИИ-архитектору учитывать корпоративные стандарты и глоссарии при проектировании процессов:

1. Нажмите кнопку **«База знаний»** в верхней панели интерфейса.
2. Выберите существующий документ для просмотра/редактирования или загрузите новый файл (`.md`, `.txt`, `.json`, `.csv`, `.xml`, `.pdf`, `.docx`).
3. Для `.pdf` и `.docx` система автоматически извлекает текстовое содержимое и сохраняет документ в персональной коллекции пользователя в БД.
4. Все документы базы знаний пользователя автоматически включаются в системный контекст (RAG) при генерации и доработке диаграмм.

## 12. Управление пользователями и безопасность

### Регистрация и авторизация
- **Логин**: символы латинского алфавита, цифры, точка, дефис и подчеркивание (`^[a-zA-Z0-9_.-]+$`), длина от 3 до 30 символов, минимум одна буква.
- **Пароль**:
  - Минимум 8 символов (латиница, цифры, спецсимволы).
  - Обязательное наличие заглавной буквы (`A-Z`), строчной буквы (`a-z`), цифры (`0-9`) и специального символа.
  - Пароль не должен совпадать с логином или содержать логин внутри себя.

### Гостевой режим (Guest Mode)
- Позволяет тестировать генерацию, редактировать код DSL, работать с визуальным холстом и экспортировать схемы без регистрации.
- Все изменения в гостевом режиме хранятся локально в сессии страницы без записи в серверную БД.

### Настройки профиля
- Клик по имени пользователя в шапке открывает окно управления профилем с вкладками **«Смена пароля»** и **«Удаление аккаунта»** (с полной каскадной очисткой проектов, диаграмм и файлов базы знаний пользователя).

## 13. Диагностика и решение типовых проблем (Troubleshooting)

### 1. `ModuleNotFoundError: No module named 'dotenv'` или `'django'`
- **Причина**: Не активировано виртуальное окружение `.venv`.
- **Решение**: Выполните `.\.venv\Scripts\Activate.ps1` (Windows) или `source .venv/bin/activate` (Linux/macOS), либо запускайте команды через `.venv\Scripts\python.exe manage.py ...`.

### 2. Ошибка PowerShell: `running scripts is disabled on this system`
- **Причина**: Политика выполнения скриптов PowerShell.
- **Решение**:
  ```powershell
  Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
  ```

### 3. Ошибка авторизации GigaChat (`401 Unauthorized`)
- **Причина**: Некорректный `GIGACHAT_AUTH_KEY` или несоответствующий `GIGACHAT_SCOPE` в файле `.env`.
- **Решение**: Для бесплатного ключа физического лица убедитесь, что установлено `GIGACHAT_SCOPE=GIGACHAT_API_PERS`, а ключ скопирован без пробелов и кавычек.

### 4. Очистка базы данных от тестовых записей после отладки
- **Решение**: Выполните команду:
  ```powershell
  python manage.py reset_db
  ```
  База данных будет полностью очищена от всех отладочных проектов и пользователей, а стандартный администратор `max` (`Admin2026!Bpmn`) будет восстановлен в чистом виде.
