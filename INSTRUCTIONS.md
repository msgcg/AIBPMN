## 1. Системные требования

- **Python**: версия `3.10`, `3.11` или более свежая версия (рекомендуется и тестировалось **только на** `3.14`).
- **Операционная система**:
  - Windows 10/11 (рекомендуется PowerShell 7+ и Windows Terminal).
  - Linux (Ubuntu 22.04+, Debian 12+, Rocky Linux 9+).
  - macOS 12+ (Monterey, Ventura, Sonoma).
- **Сетевой доступ**: исходящее HTTPS-подключение к API Сбера (`https://ngw.devices.sberbank.ru:9443` и `https://gigachat.devices.sberbank.ru`).
- **Браузер**: современный веб-браузер с поддержкой ES6+ и SVG (Yandex browser, Chrome, Edge, Firefox, Safari).

## 2. Подготовка окружения и установка зависимостей

### Windows 11 / 10 (PowerShell)

1. Откройте **Windows Terminal** или **PowerShell** от имени вашего пользователя.
2. Перейдите в корневую директорию проекта:

   ```powershell
   cd "C(or other):\path\to\AIBPMN"
   ```
3. Создайте виртуальное окружение Python:

   ```powershell
   python -m venv .venv
   ```
4. Если при активации возникает ошибка выполнения скриптов (`execution of scripts is disabled on this system`), однократно разрешите запуск локальных скриптов для текущего пользователя:

   ```powershell
   Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
   ```
5. Активируйте виртуальное окружение:

   ```powershell
   .\.venv\Scripts\Activate.ps1
   ```

   *(В начале строки терминала появится префикс `(.venv)`)*.
6. Обновите `pip` и установите зависимости проекта:

   ```powershell
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

### Linux / macOS (Bash / Zsh)

1. Откройте терминал и перейдите в папку проекта:
   ```bash
   cd /path/to/AIBPMN
   ```
2. Создайте и активируйте виртуальное окружение:
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```
3. Обновите `pip` и установите зависимости:
   ```bash
   python3 -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

## 3. Получение и настройка API-ключа Сбер GigaChat

Для работы генеративного ИИ-архитектора требуется бесплатный доступ к **GigaChat API**:

1. Перейдите на портал разработчиков Сбера: [developers.sber.ru](https://developers.sber.ru/).
2. Войдите с помощью **Сбер ID** (или создайте учетную запись).
3. Перейдите в раздел **«Кабинет»** $\rightarrow$ **«GigaChat API»**.
4. Создайте новый проект (для личного использования выберите тип **«Физлицо»** — предоставляется бесплатный ежемесячный лимит токенов).
5. > **ВНИМАНИЕ!!! На момент написания кода Sber не предоставляет доступ к используемой в проекте модели на платной основе юрлицам и ИП.**
   >
6. В созданном проекте скопируйте **«Авторизационные данные»** (строка вида `Authorization data` в формате Base64, либо пару `Client ID` и `Client Secret`).
7. Скопированное значение будет указано в параметре `GIGACHAT_AUTH_KEY` в файле `.env`.

> [!NOTE]
> В AIBPMN встроен автоматический менеджер OAuth-токенов: система самостоятельно запрашивает временный токен доступа у шлюза Сбера и безопасно обновляет его каждые 30 минут без необходимости ручного перезапуска.
>
> **При этом ручное тестирование проводилось через единый ключ авторизации, так что предпочтительней использовать единый ключ авторизации.**

## 4. Конфигурация переменных окружения (.env)

### Режим разработки (Development)

1. Скопируйте шаблон `.env.example` в файл `.env`:

   - **PowerShell**:
     ```powershell
     Copy-Item .env.example .env
     ```
   - **Bash**:
     ```bash
     cp .env.example .env
     ```
2. Откройте файл `.env` в текстовом редакторе и настройте параметры:

   ```dotenv
   # Режим окружения: dev
   DJANGO_ENV=dev
   DJANGO_DEBUG=True
   DJANGO_SECRET_KEY=django-insecure-aibpmn-architecture-suite-2026-key

   # Разрешенные хосты (через запятую)
   DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1

   # Авторизация GigaChat (API Сбера)
   GIGACHAT_AUTH_KEY=ВАШ_КЛЮЧ_АВТОРИЗАЦИИ_GIGACHAT
   GIGACHAT_SCOPE=GIGACHAT_API_PERS
   GIGACHAT_MODEL=GigaChat-3-Ultra
   ```

   > **Параметры Scope:**
   >
   > - `GIGACHAT_API_PERS` — для физических лиц (по умолчанию).
   > - `GIGACHAT_API_CORP` — для юридических лиц / корпоративных договоров.
   >
   > **Параметры моделей:**
   >
   > - `GigaChat-3-Ultra` — флагманская модель с максимальным качеством проектирования архитектуры процессов.
   > - `GigaChat-Pro` — быстрая продвинутая модель.
   > - `GigaChat` — базовая облегченная модель.
   >

### Режим промышленной эксплуатации (Production)

Для развертывания на сервере или боевом стенде используйте шаблон `.env.production.example`:

```dotenv
DJANGO_ENV=production
DJANGO_DEBUG=False

# Сгенерируйте уникальный стойкий секретный ключ (не менее 50 символов)
DJANGO_SECRET_KEY=generate-a-strong-random-secret-key-here-minimum-50-characters

# Доменные имена вашего сервера
DJANGO_ALLOWED_HOSTS=aibpmn.yourdomain.com,127.0.0.1

# Доверенные источники для защиты от CSRF (обязательно с протоколом https://)
DJANGO_CSRF_TRUSTED_ORIGINS=https://aibpmn.yourdomain.com

# Настройки безопасности SSL и cookie
DJANGO_COOKIE_SECURE=True
DJANGO_SECURE_SSL_REDIRECT=True
DJANGO_HSTS_SECONDS=31536000

# Авторизация GigaChat
GIGACHAT_AUTH_KEY=ВАШ_БОЕВОЙ_КЛЮЧ_GIGACHAT
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-3-Ultra
```

## 5. База данных, миграции и рут-пользователь по умолчанию

Проект использует реляционную базу данных SQLite (по умолчанию файл `db.sqlite3` в корне). В ней хранятся учетные записи пользователей, проекты, диаграммы, история чатов и база знаний в Base64.

1. Примените миграции схемы данных:
   ```powershell
   python manage.py migrate
   ```

2. **Рут-пользователь по умолчанию для панели управления**:
   При выполнении миграций автоматически настраивается учетная запись суперпользователя:
   - **Логин**: `max`
   - **Пароль**: `Admin2026!Bpmn`
   - **URL панели администратора**: [http://127.0.0.1:8000/admin/](http://127.0.0.1:8000/admin/)

   > В панели управления доступны расширенные функции:
   > - Управление проектами с подсчетом диаграмм и связью с владельцами.
   > - Редактирование диаграмм с предпросмотром сгенерированного BPMN 2.0 XML и истории чата.
   > - Инспекция сообщений диалога с цветовыми бейджами ролей (пользователь, ассистент, система).
   > - Управление файлами базы знаний с декодированием Base64 и встроенным предпросмотром текста.

3. *(Опционально)* Создание дополнительного суперпользователя:
   ```powershell
   python manage.py createsuperuser
   ```
   Следуйте подсказкам в консоли (введите логин, email и пароль).

> [!TIP]
> При первом запуске и открытии базы знаний системные руководства по языку BPMN-as-Code автоматически загрузятся из каталога `knowledge_base/`.

## 6. Способы запуска приложения

### Способ 1: Режим разработки через терминал

Запустите встроенный сервер Django:

```powershell
python manage.py runserver
```

Сервер запустится по адресу: `http://127.0.0.1:8000/`.

Если требуется слушать все сетевые интерфейсы (например, для проверки с мобильного телефона в локальной сети Wi-Fi):

```powershell
python manage.py runserver 0.0.0.0:8000
```

*(Убедитесь, что IP вашего ПК добавлен в `DJANGO_ALLOWED_HOSTS` в `.env`).*

---

### Способ 2: Запуск и отладка в Visual Studio Code (F5)

В корневой папке проекта настроена директория `.vscode/` с готовыми конфигурациями запуска:

1. Откройте папку проекта `AIBPMN` в **VS Code**.
2. Убедитесь, что в правом нижнем углу выбран интерпретатор из `.venv` (`Python 3.12 (.venv)`).
3. Нажмите `Ctrl+Shift+D` (вкладка **Run and Debug**).
4. В выпадающем списке вверху выберите нужный профиль:
   - [▷] **`Django: Отладка (Development / Dev)`**: запуск сервера разработки на `0.0.0.0:8000` с дебаггером и горячей перезагрузкой.
   - [⚙] **`Django: Продакшн (Production / Prod)`**: запуск с боевыми настройками безопасности `prod.py` и флагом `--insecure` для статики.
   - [✓] **`Django: Тесты (Run Tests)`**: запуск полного набора автотестов.
5. Нажмите клавишу **F5** (или зелёную кнопку Play).

Вы можете ставить точки останова (Breakpoints) в любых Python-файлах (`views.py`, `models.py`, `compiler_service.py` и др.) и отслеживать переменные в реальном времени.

---

### Способ 3: Локальное тестирование продакшн-конфигурации

Для проверки поведения приложения с выключенным `DEBUG` на локальной машине:

```powershell
python manage.py runserver 0.0.0.0:8000 --insecure --settings=aibpmn_project.settings.prod
```

*Флаг `--insecure` позволяет встроенному серверу отдавать статические файлы (CSS, JS) даже при `DEBUG = False`.*

---

### Способ 4: Промышленное развертывание на Linux-сервере (Gunicorn + Nginx)

1. Соберите статические файлы:
   ```bash
   python manage.py collectstatic --noinput
   ```
2. Установите WSGI-сервер `gunicorn`:
   ```bash
   pip install gunicorn
   ```
3. Пример юнита **systemd** (`/etc/systemd/system/aibpmn.service`):
   ```ini
   [Unit]
   Description=AIBPMN Architect Django Application
   After=network.target

   [Service]
   User=www-data
   Group=www-data
   WorkingDirectory=/var/www/AIBPMN
   ExecStart=/var/www/AIBPMN/.venv/bin/gunicorn \
       --workers 3 \
       --bind 127.0.0.1:8000 \
       aibpmn_project.wsgi:application
   Restart=always

   [Install]
   WantedBy=multi-user.target
   ```
4. Пример конфигурации **Nginx** (`/etc/nginx/sites-available/aibpmn`):
   ```nginx
   server {
       listen 80;
       server_name aibpmn.yourdomain.com;
       return 301 https://$host$request_uri;
   }

   server {
       listen 443 ssl http2;
       server_name aibpmn.yourdomain.com;

       ssl_certificate /etc/letsencrypt/live/aibpmn.yourdomain.com/fullchain.pem;
       ssl_certificate_key /etc/letsencrypt/live/aibpmn.yourdomain.com/privkey.pem;

       client_max_body_size 25M;

       location /static/ {
           alias /var/www/AIBPMN/static_collected/;
           expires 30d;
           access_log off;
       }

       location / {
           proxy_pass http://127.0.0.1:8000;
           proxy_set_header Host $host;
           proxy_set_header X-Real-IP $remote_addr;
           proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
           proxy_set_header X-Forwarded-Proto $scheme;
       }
   }
   ```

## 7. Запуск автоматических тестов

В проекте реализован комплексный набор из **54 автоматических тестов**, покрывающий все ключевые модули:

- Регистрацию, аутентификацию, смену пароля и удаление аккаунтов.
- Изоляцию персональных данных и гостевой режим.
- Парсинг, валидацию и компиляцию языка BPMN-as-Code.
- Фильтрацию файлов базы знаний и кодирование в Base64.
- Модели и контроллеры API диаграмм, сообщений и проектов.
- Работу PWA, манифеста, фавиконок и безопасного Service Worker (проверка отсутствия вмешательства в CSRF).
- Динамическую генерацию `robots.txt` и `sitemap.xml`, а также консольную команду `generate_seo`.
- Создание и права рут-пользователя `max`, корректность регистрации моделей в панели администратора.

Для запуска тестов выполните:

```powershell
python manage.py test architect
```

При успешном прохождении тестов вывод завершится сообщением:

```text
Ran 62 tests in ...s
OK
```

## 8. Progressive Web App (PWA) и кроссплатформенная установка

Приложение полностью оптимизировано под стандарт **PWA** для всех платформ:
- **Android**: установка через всплывающую подсказку браузера Chrome/Edge или пункт меню «Установить приложение».
- **iOS / iPadOS (Safari)**: нажмите кнопку «Поделиться» $\rightarrow$ «На экран "Домой"».
- **Windows / macOS / Linux**: иконка установки в адресной строке Chrome/Edge («Установить AIBPMN Architect»).

### Особенности Service Worker (`sw.js`) и безопасность Django
- **Строгая изоляция CSRF и авторизации**: воркер путей и навигации намеренно **не переносится в `sw.js`**.
- Любые не-GET запросы (`POST`, `PUT`, `DELETE`), навигационные переходы браузера (`mode: 'navigate'`) и обращения к `/api/` и `/admin/` **никогда не перехватываются воркером** и передаются напрямую серверу Django. Это гарантирует сохранение актуальных CSRF-токенов и сессий пользователей.
- Service Worker ускоряет работу приложения, кешируя исключительно неизменяемые статические файлы (CSS, JS, иконки, шрифты).

## 9. Автогенерация robots.txt и sitemap.xml

1. **Динамическая генерация в реальном времени**:
   - `GET /robots.txt` — автоматически формирует актуальный файл директив для поисковых систем с запретом индексации `/api/` и `/admin/` и ссылкой на карту сайта.
   - `GET /sitemap.xml` — генерирует валидную XML-карту сайта со спецификацией `sitemaps.org/schemas/sitemap/0.9`.
2. **Консольная команда для создания статических файлов**:
   Для Nginx или статического хостинга доступна встроенная команда Django:
   ```powershell
   python manage.py generate_seo --domain=https://ваш-домен.ru
   ```
   Файлы будут автоматически сгенерированы в каталог статических файлов.

## 10. Работа с базой знаний и RAG

База знаний позволяет ИИ-архитектору учитывать стандарты и шаблоны вашей компании при генерации процессов:

1. Откройте в интерфейсе вкладку **«База знаний»**.
2. Нажмите кнопку **«Загрузить файл»** и выберите документ (`.md`, `.txt`, `.json`, `.csv`, `.xml` и др.).
3. Система проверит файл на отсутствие бинарного вредоносного содержимого и сохранит его в изолированную персональную коллекцию в базе данных.
4. Вы можете:
   - Просматривать содержимое документов с подсветкой синтаксиса.
   - Скачивать исходные файлы кнопкой **«Скачать»**.
   - Удалять ненужные файлы.
5. При отправке запроса в чат содержимое базы знаний автоматически используется моделью как контекст предметной области.

## 11. Управление пользователями и безопасность

### Регистрация и авторизация

- **Логин**: разрешены только символы латинского алфавита, цифры, дефис и символ подчеркивания (`^[a-zA-Z0-9_-]+$`). Длина от 3 до 30 символов.
- **Пароль**: строгая проверка сложности в реальном времени:
  - Минимум 8 символов.
  - Только латинские символы и стандартные спецсимволы (кириллица строго запрещена).
  - Наличие заглавной буквы (`A-Z`), строчной буквы (`a-z`), цифры (`0-9`) и специального символа (`!@#$%^&*` и др.).
  - Пароль не должен содержать логин пользователя или являться его подстрокой.

### Гостевой режим (Guest Mode)

- Пользователь может тестировать генерацию, писать код и просматривать граф без регистрации.
- При этом проекты и персональная база знаний не сохраняются на сервере, защищая приватность.

### Настройки профиля

- Клик по бейджу профиля в шапке открывает модальное окно:
  - **Смена пароля**: требует ввода текущего пароля и удовлетворения всем критериям сложности для нового пароля.
  - **Удаление аккаунта**: требует подтверждения паролем и осознанного согласия. Удаляет аккаунт и каскадно стирает из базы данных все связанные проекты, диаграммы, сообщения чата и файлы базы знаний.

## 12. Диагностика и решение типовых проблем (Troubleshooting)

### 1. `ModuleNotFoundError: No module named 'dotenv'` или `'django'`

- **Причина**: Не активировано виртуальное окружение, либо запущен системный интерпретатор Python.
- **Решение**: Убедитесь, что окружение активировано (`.\.venv\Scripts\Activate.ps1` на Windows или `source .venv/bin/activate` на Linux). В терминале должен отображаться префикс `(.venv)`. Либо запускайте напрямую через `.venv\Scripts\python.exe manage.py runserver`.

### 2. Ошибка PowerShell: `running scripts is disabled on this system`

- **Причина**: Политика безопасности PowerShell по умолчанию блокирует запуск внешних скриптов.
- **Решение**: Выполните команду в PowerShell:
  ```powershell
  Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
  ```

### 3. Ошибка авторизации GigaChat (`401 Unauthorized` или `SSL Certificate Error`)

- **Причина**: Неверный `GIGACHAT_AUTH_KEY` в файле `.env`, либо неверно указан `GIGACHAT_SCOPE`.
- **Решение**:
  - Если у вас личный аккаунт физлица, проверьте: `GIGACHAT_SCOPE=GIGACHAT_API_PERS`.
  - Убедитесь, что в `GIGACHAT_AUTH_KEY` скопирована полная строка авторизации без лишних пробелов или кавычек.
  - Убедитесь, что ваш файрвол не блокирует обращения к шлюзу Сбера по порту `9443`.

### 4. Стили или скрипты не загружаются в браузере

- **Причина**: Кэш браузера или запуск продакшна без сборки статики.
- **Решение**:
  - Нажмите `Ctrl+F5` (или `Cmd+Shift+R` на Mac) для принудительной перезагрузки страницы без кэша.
  - Если запущен режим `prod`, используйте флаг `--insecure` при локальном запуске: `python manage.py runserver --insecure --settings=aibpmn_project.settings.prod`.

### 5. `DisallowedHost at /`

- **Причина**: Обращение к серверу происходит по хосту или IP, не указанному в `ALLOWED_HOSTS`.
- **Решение**: Добавьте ваш хост или IP-адрес в параметр `DJANGO_ALLOWED_HOSTS` файла `.env` через запятую:
  ```dotenv
  DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1,192.168.1.50
  ```
