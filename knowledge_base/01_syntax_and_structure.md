# BPMN-as-Code: Базовый синтаксис и структура процесса

Каждая диаграмма описывается на декларативном языке BPMN-as-Code (DSL).
Каждый процесс ДОЛЖЕН начинаться с объявления имени:
```bac
process "Название бизнес-процесса"
```

## Пулы и дорожки ролей (Pools & Swimlanes)
Для разграничения зон ответственности участников процесса объявляются пулы и дорожки:
```bac
pool: p_main "Организация"
lane: l_employee "Сотрудник" in p_main
lane: l_manager "Руководитель" in p_main
lane: l_accountant "Бухгалтерия" in p_main
```
Внешние участники (клиенты, банки, внешние контрагенты) при необходимости объявляются отдельным свернутым пулом:
```bac
pool: p_client "Клиент (внешний)"
```

## Правила синтаксиса
1. **Идентификаторы узлов (ID)** пишутся на латинице в формате snake_case (например: `order_received`, `check_inventory`, `manager_approval`). ID обязаны быть уникальными.
2. **Лейблы узлов** заключаются в двойные кавычки (например: `"Заказ получен"`, `"Проверить остатки на складе"`).
3. **Лейблы задач** должны быть глагольными формами: «Проверить данные», «Сформировать счет», «Отправить уведомление».
4. **Комментарии** начинаются с символа `#` и могут располагаться на отдельной строке или в конце строки.
5. **Объявление узлов** выполняется через ключевые слова с двоеточием: `start:`, `end:`, `task:`, `gateway:`, `subprocess:`, `call:`, `note:`, `data:`, `datastore:`.
6. **Привязка к дорожке**: выполняется через модификатор `in <lane_id>` (например: `task: t1 "Проверить заявку" user in l_manager`).
7. **Связи (flows)**: объявляются через стрелки `->` (например: `s -> t1 -> g1`).
