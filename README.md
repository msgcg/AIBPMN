# AIBPMN Architect — Проектирование бизнес-процессов с ИИ (BPMN-as-Code)

> [!IMPORTANT]
> ## Инструкция: быстрый запуск за 3 минуты

### Шаг 1. Запуск приложения на компьютере

Убедитесь, что на компьютере установлен **Python 3.10+** ([python.org](https://www.python.org/downloads/)) и **Git** ([git-scm.com](https://git-scm.com/)). При установке Python на Windows отметьте пункт **«Add python.exe to PATH»**.

#### Вариант для Windows (PowerShell):

1. Откройте **PowerShell** или **Windows Terminal**.
2. Клонируйте репозиторий и перейдите в папку проекта:

   ```powershell
   git clone https://github.com/msgcg/AIBPMN.git
   cd AIBPMN
   ```
3. Создайте и активируйте изолированное виртуальное окружение:

   ```powershell
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

   *(Если появится ошибка о запрете выполнения скриптов, выполните команду `Set-ExecutionPolicy RemoteSigned -Scope CurrentUser` и повторите активацию).*
4. Установите зависимости проекта:

   ```powershell
   pip install -r requirements.txt
   ```
5. (Необязательно) Создайте файл настроек Django `.env` из шаблона:

   ```powershell
   Copy-Item .env.example .env
   ```
6. Инициализируйте базу данных (локальный файл `db.sqlite3` и учетная запись администратора создадутся автоматически):

   ```powershell
   python manage.py migrate
   ```
7. Запустите сервер:

   ```powershell
   python manage.py runserver
   ```

#### Вариант для Linux / macOS:

```bash
# 1. Скачивание и переход в папку
git clone https://github.com/msgcg/AIBPMN.git
cd AIBPMN

# 2. Создание и активация окружения
python3 -m venv .venv
source .venv/bin/activate

# 3. Установка зависимостей
pip install -r requirements.txt

# 4. (Необязательно) Настройка файла .env для параметров Django
cp .env.example .env

# 5. База данных и запуск
python manage.py migrate
python manage.py runserver
```

## О проекте

**AIBPMN Architect** объединяет декларативный подход «диаграмма как код» (*BPMN-as-Code*) с возможностями больших языковых моделей (**Сбер GigaChat API**) и интерактивным визуальным моделированием по стандарту **BPMN 2.0**.

Вместо ручного перетаскивания сотен фигур аналитик или архитектор описывает бизнес-процесс на естественном языке в чате (или загружает текстовый регламент `.docx` / `.pdf` / `.md`), после чего система:

1. Анализирует требования с учетом корпоративных правил и персональной базы знаний (RAG-контекст).
2. Проектирует структуру пулов, дорожек, задач, шлюзов и событий на языке **BPMN-as-Code (DSL)**.
3. Проверяет логическую целостность процесса: выявляет логические разрывы (не додумывая отсутствующие связи), формирует сводный отчет валидации и задает проактивные уточняющие вопросы по неоднозначным местам регламента.
4. Компилирует DSL в валидную схему **BPMN 2.0 XML** с автоматическим иерархическим размещением элементов (Auto-Layout) без наслоения текста.
5. Обеспечивает сквозную трассировку (Traceability) между предложениями исходного текста/документа, строками кода DSL и графическими блоками на холсте.

## Ключевые функциональные возможности

### 1. Интеллектуальный ИИ-архитектор (GigaChat API)

- **Интерактивное подключение GigaChat API из браузера**: при попытке использовать ИИ без настроенного ключа автоматически открывается модальное окно авторизации GigaChat. После проверки ключа система сразу же продолжает выполнение отправленного запроса. В гостевом режиме ключ хранится в cookie браузера, а у авторизованных пользователей — в базе данных.
- **Генерация процессов с нуля и итеративная доработка**: построение схем по текстовому описанию и пошаговая модификация в диалоге с сохранением контекста.
- **Автоматическое самоисправление синтаксиса (Auto-Retry до 5 попыток)**: при обнаружении синтаксической ошибки компилятор передает диагностику обратно в GigaChat, и модель автоматически исправляет код до выдачи ответа пользователю.
- **Детекция логических разрывов без галлюцинаций связей**: если в исходном описании процесса пропущен переход между этапами, система намеренно не рисует вымышленную стрелку, оставляя разрыв потока управления заметным на схеме и предупреждая аналитика в отчете валидации.
- **Раскрываемый «Отчет валидации процесса»**: автоматическая сводка в карточке ответа ассистента (количество стартовых и конечных событий, задач, развилок, циклов возврата, предупреждения о висячих узлах и ролях).
- **Раскрываемый блок «Уточняющие вопросы по регламенту»**: если в описании не указана ветка отказа, роль исполнителя или условие перехода, агент формирует 1–3 уточняющих вопроса со встроенными кнопками быстрых ответов (чипами) для доработки схемы в один клик.
- **Прикрепление файлов в чат**: поддержка отправки документов `.pdf`, `.docx`, `.md`, `.txt`, `.json`, `.csv`, `.xml` напрямую в сообщение чата с автоматическим извлечением текста.

### 2. Сквозной трейсинг (Текст / Документ <-> Код DSL <-> Схема BPMN)

- **Синхронизация при клике на элемент диаграммы**:
  - В редакторе кода BPMN-as-Code автоматически подсвечиваются и прокручиваются строки, отвечающие за выбранный блок и его потоки.
  - В ИИ-чате подсвечивается исходное предложение в сообщении пользователя, из которого был сгенерирован данный шаг.
  - Если схема построена по прикрепленному файлу (`.md`, `.docx`, `.pdf`, `.txt`), под карточкой документа в чате появляется интерактивная подсказка с найденной цитатой.
- **Перетаскиваемое модальное окно просмотра документа**:
  - Клик по карточке прикрепленного файла открывает компактное плавающее окно с полным текстом документа и подсветкой всех предложений, связанных с элементами схемы.
  - Окно можно свободно перемещать мышью или пальцем за заголовок (Drag & Drop с удержанием в границах экрана), чтобы оно не перекрывало схему.
  - Клик по любому подсвеченному предложению в документе или чате выделяет и центрирует соответствующий узел на холсте BPMN и подсвечивает его код в редакторе.

### 3. Трехсторонняя синхронизация (Чат <-> Код <-> Визуальный холст)

- **Редактор кода BPMN-as-Code (DSL)**:
  - Подсветка синтаксиса на базе расширенной грамматики `Prism.js` для темной и светлой тем.
  - Полноэкранный режим редактирования кода и встроенный интерактивный справочник по синтаксису с готовыми примерами и вставкой в один клик.
  - Построчная подсветка трейсинга синхронно с выбранным узлом на схеме.
- **Визуальный интерактивный редактор BPMN 2.0 (`bpmn-js`)**:
  - Редактирование фигур, пулов, дорожек, шлюзов и связей непосредственно на холсте с автоматической обратной декомпиляцией изменений из BPMN 2.0 XML в код DSL.
  - Умная авторасстановка элементов (Auto-Layout) по дорожкам ответственности с защитой от наложения подписей.
  - Полная поддержка сенсорных экранов (панорамирование одним пальцем, масштабирование жестом *Pinch-to-Zoom*, перетаскивание узлов).

### 4. Импорт и экспорт (5 форматов экспорта и 2 формата импорта)

- **Экспорт**:
  - `.bpmn` — стандартный файл BPMN 2.0 XML с координатами диаграммы.
  - `.bac` — исходный код процесса на языке BPMN-as-Code.
  - `.svg` — масштабируемое векторное изображение.
  - `.png` — растровое изображение высокой четкости (2x).
  - `.pdf` — готовый документ с автоматическим подбором ориентации листа.
- **Импорт**:
  - Загрузка файлов `.bac` (код DSL) и `.bpmn` / `.xml` (с автоматической декомпиляцией XML-схемы в код BPMN-as-Code).

### 5. Мультипроектность, персональная база знаний (RAG) и безопасность

- **Проекты и история диалогов**: создание, переименование и удаление проектов и диаграмм, полное сохранение истории сообщений с возможностью одиночного и пакетного удаления.
- **Персональная база знаний (RAG)**:
  - Изолированное хранилище документов каждого пользователя в БД (в кодировке Base64) с предзагрузкой системных правил BPMN-as-Code.
  - Поддержка текстовых форматов (`.md`, `.txt`, `.json`, `.csv`, `.xml`) и автоматическое извлечение текста из `.pdf` и `.docx`.
  - Фильтрация потенциально опасных исполняемых файлов, просмотр, редактирование и скачивание документов.
- **Аутентификация, хранение ключей GigaChat и управление профилем**:
  - Строгая валидация логина и пароля в реальном времени при регистрации и смене пароля.
  - Полноценный гостевой режим (работа в памяти браузера без записи проектов в БД сервера; ключ GigaChat API хранится в cookie браузера).
  - Для авторизованных пользователей ключ GigaChat API хранится в базе данных (`UserGigaChatCredential`).
  - Удаление аккаунта с каскадной очисткой всех связанных данных.
- **Чистота репозитория и автосоздание администратора**:
  - Локальная база данных `db.sqlite3` исключена из Git-репозитория (`.gitignore`), благодаря чему отладочные изменения никогда не попадают в коммиты.
  - Учетная запись администратора и пользователя `max` (`Admin2026!Bpmn`) автоматически создается при миграциях, первом запросе к серверу или входе в `/admin/` и `/`.
  - Для быстрой очистки локальной БД от отладочных данных предусмотрена команда `python manage.py reset_db`.

### 6. Progressive Web App (PWA) и SEO

- **PWA**: установка приложения как самостоятельного окна на Windows, macOS, Linux, Android и iOS; полный набор иконок и `manifest.json`.
- **Безопасный Service Worker (`sw.js`)**: кеширует только статические ресурсы (CSS, JS, шрифты, иконки) по стратегии *Stale-While-Revalidate*, никогда не перехватывая навигацию, `/api/`, `/admin/` и CSRF-запросы Django.
- **SEO**: динамическая генерация `/robots.txt` и `/sitemap.xml`, а также CLI-команда `python manage.py generate_seo`.

## Спецификация языка BPMN-as-Code (DSL)

Язык **BPMN-as-Code** — декларативный построчный синтаксис для описания структуры пулов, дорожек, задач, событий, развилок и потоков управления.

### Пример процесса с пулом и дорожками:

```text
process "Согласование командировки"

pool: p_corp "Организация"
lane: l_employee "Сотрудник" in p_corp
lane: l_manager "Руководитель отдела" in p_corp
lane: l_fin "Бухгалтерия и финансы" in p_corp

start: s_req "Подать заявку на командировку" in l_employee
task: t_check "Проверить лимит бюджета" service in l_manager
gateway: g_budget "В рамках бюджета?" exclusive in l_manager

task: t_review "Согласование руководителем" user in l_manager
gateway: g_manager "Решение руководителя" exclusive in l_manager
task: t_rework "Доработать параметры поездки" user in l_employee

task: t_booking "Бронирование билетов и выплата суточных" service in l_fin

end: e_approved "Командировка согласована" in l_fin
end: e_rejected "Заявка отклонена" in l_manager

s_req -> t_check -> g_budget
g_budget --[В лимите]--> t_review -> g_manager
g_budget --[Превышен]--> e_rejected

g_manager --[Одобрено]--> t_booking -> e_approved
g_manager --[На доработку]--> t_rework
t_rework -> t_review
g_manager --[Отклонено]--> e_rejected
```

### Основные конструкции языка:

- **Объявление процесса**:
  - `process "Название процесса"`
- **Пулы и дорожки (Swimlanes)**:
  - `pool: <id> "Название пула"`
  - `lane: <id> "Название роли / отдела" in <pool_id>`
- **События**:
  - `start: <id> "Название" [timer|message|signal] [in <lane_id>]`
  - `end: <id> "Название" [message|error|terminate] [in <lane_id>]`
  - `event: <id> "Название" [timer|message|error|signal] [on <task_id>] [in <lane_id>]` (промежуточные и граничные события)
- **Активности (Задачи и подпроцессы)**:
  - `task: <id> "Название" [user|service|script|manual|send|receive|business] [in <lane_id>]`
  - `subprocess: <id> "Название подпроцесса" [in <lane_id>]`
  - `call: <id> "Название вызываемого процесса" [in <lane_id>]`
- **Шлюзы (Развилки и слияния)**:
  - `gateway: <id> "Вопрос или условие?" [exclusive|parallel|inclusive|event] [in <lane_id>]`
- **Потоки управления и сообщений**:
  - `a -> b -> c` — последовательный поток управления (`SequenceFlow`).
  - `gw --[Условие]--> target` — условный переход из шлюза.
  - `a -.-> b` или `a -.[Документ].-> b` — межпуловый поток сообщений (`MessageFlow`).

## Автоматическое тестирование и обслуживание БД

В проекте реализовано **86 автоматических тестов**, проверяющих:

- Регистрацию, аутентификацию, автосоздание администратора `max`, смену пароля и удаление аккаунтов (`test_auth.py`).
- Компиляцию BPMN-as-Code в BPMN 2.0 XML, декомпиляцию XML обратно в DSL и обработку синтаксических ошибок (`test_compiler.py`).
- Генерацию и доработку схем через GigaChat API, механизм автоматических повторных попыток (до 5 ретраев при невалидном DSL), отчеты валидации, проактивные вопросы и извлечение трейсинга (`test_gigachat.py`, `test_views.py`).
- Загрузку документов (`.md`, `.txt`, `.docx`, `.pdf`) в чат и в персональную базу знаний, фильтрацию опасных расширений (`test_knowledge_base.py`, `test_views.py`).
- Работу PWA, манифеста, безопасного Service Worker, `robots.txt`, `sitemap.xml` и правовых страниц (`test_pwa_seo.py`, `test_legal.py`).

Запуск полного набора тестов:

```bash
python manage.py test architect
```

Очистка локальной базы данных после отладки (удаляет все проекты, историю чатов и тестовых пользователей, оставляя только чистого пользователя/администратора `max` с паролем `Admin2026!Bpmn`):

```bash
python manage.py reset_db
```
